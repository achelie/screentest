How to test

  1. Move the window to the intended display and set browser page zoom to 100%. Wait for the live measurements to settle.
  2. Compare Reported screen with Layout viewport and Visible viewport. The screen and viewport values use CSS pixels; the viewport describes browser content space.
  3. Read Pixel ratio and Estimated output pixels together. The estimate multiplies reported screen size by DPR; DPR depends on system scale and browser page zoom.
  4. Resize the window, enter fullscreen, or rotate the phone and watch the viewport update. Record the values with zoom and system scale, then compare with system display settings and the monitor menu.

What counts as normal

Use these references for this visual check. They are not a manufacturer acceptance standard or a hardware certification.

  • Live values react to window or orientation changes. A smaller CSS screen size or viewport can be expected with scaling and browser controls; it does not by itself mean missing physical pixels.

How to read your result

Reported screen is smaller than the panel specification
CSS pixels and system scaling can explain this. For example, a 4K output at 200% scale may report about 1920 × 1080 CSS pixels.
The viewport is smaller than the screen
Window size, browser bars, sidebars, and system UI reduce the content area.
DPR or estimated output changes with zoom
Page zoom can change DPR, so the calculated output remains an estimate. Pinch zoom usually changes the visible viewport scale instead.
Frame cadence or color buffer looks unexpected
Cadence estimates browser callbacks, not display Hz. Color buffer is a browser value, not proof of native panel bit depth.

Browser APIs do not reliably reveal the physical panel resolution, EDID model, physical pixel density, or real refresh rate. Estimated output pixels are a calculation, not a direct hardware measurement.

If you cannot get a result

  1. Restore 100% page zoom and keep the window on one display. Compare again after the values settle.
  2. Check actual resolution and scaling in system settings and the display's own menu. Use those to verify output rather than the estimated pixel label alone.
  3. If a field says Not reported or Not supported, try another browser. Keep this tab visible for frame timing; an unavailable API is not a hardware failure.

What to check

The estimate matches the resolution selected in system settings
That is a useful consistency check. For a 3840 × 2160 output, the page may still report a smaller CSS screen when scaling is enabled.
Moving the window to another monitor changes DPR or dimensions
That is expected when the displays use different scaling or resolutions. Keep the checker on the monitor you are investigating.
Fullscreen viewport is smaller than the reported screen
Browser UI, mobile safe areas, zoom, or operating-system reservations may still affect the usable page area. Compare the available-area and viewport rows.
A high-refresh display shows about 60 browser fps
Check the selected display refresh rate, power saving, browser load, and which monitor owns the window. Then use the Screen Tearing Test for a moving comparison.

Screen resolution checker FAQ

What is my screen resolution?

Read the Estimated output pixels result first, then compare it with the resolution selected in your operating system. The Reported screen row shows the browser's CSS-pixel view of the same display.

Why does my 4K display show 1536 × 864?

That usually means interface scaling is active. At a DPR of 2.5, 1536 × 864 CSS pixels map to an estimated 3840 × 2160 device-pixel output, so text stays readable while the display keeps its dense pixel grid.

What is the difference between CSS pixels and estimated output pixels?

CSS pixels size browser interfaces and web layouts. Estimated output pixels multiply that reported size by DPR to approximate the device-pixel output currently used for the page.

Why is my device pixel ratio 1.25 or 1.5?

Fractional values are common when desktop scaling is set to 125% or 150%. Browser zoom can also affect DPR, so use 100% page zoom when you want the cleanest comparison.

Why does the result change when I move the window?

Each monitor can use a different resolution and scaling value. The checker updates after the browser moves to a display with a different screen size or DPR.

Why is the browser viewport smaller than the screen?

Tabs, the address bar, window borders, taskbars, mobile browser controls, and on-screen keyboards can all reduce the page area. Fullscreen removes most browser chrome so you can compare again.

Why does browser frame cadence differ from my monitor's refresh rate?

The estimate measures animation callbacks delivered to this page. Browser workload, background throttling, power saving, compositing, and frame pacing can make it differ from the refresh rate selected for the monitor.

Can I check an external monitor with this page?

Yes. Move the entire browser window onto that monitor, wait for the values to update, and enter fullscreen there. This page checks the display holding the window and does not request access to every connected screen.
